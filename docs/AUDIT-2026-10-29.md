# Bug hunt and upgrade report (2026-10-29)

Scope: current `main` after commit 331259a. Fixes are in migration `202610240003_security_and_integrity_fixes.sql` plus three code edits.

## How it was tested
- All migrations applied to a scratch PostgreSQL 16 with stubbed Supabase roles/schemas.
- Each database fix was attacked as `authenticated` with a spoofed `request.jwt.claim.sub` and confirmed blocked/working.
- TypeScript/Deno files were only syntax-checked (npm registry unreachable here: no build, no vitest, no Deno run, no browser test). **Run `npm run build` and the test suite in CI before relying on the code edits.**

## Confirmed bugs (fixed)
| # | Severity | Bug | Fix |
|---|---|---|---|
| 1 | Critical | Organisation owner could insert/update own `sport_billing_accounts` row and self-activate a paid plan | Insert limited to a free account; UPDATE revoked |
| 2 | Critical | Owner could create/alter `sport_service_orders` with any price/status | Direct writes revoked; `request_sport_service()` RPC with fixed prices |
| 3 | High | Trial sessions: `billing_status`/`paid_at` writable by owner, bypassing the trial-day fee | Trigger locks these fields for non-admins |
| 4 | High | Athletes could self-verify statistics and achievements | Trigger forces `self_reported`; only admin verifies; editing verified content resets it |
| 5 | High | Evidence reviews could be inserted pre-approved | Forced to `pending` |
| 6 | High | Endorsements/references could be self-approved by the athlete | Role-split state machine trigger |
| 7 | Medium | Reference invites failed (`gen_random_bytes` not on search_path; RLS on invites) | Functions are security definer with `public, extensions` path |
| 8 | Medium | Athletes could not withdraw an application (no UPDATE policy) | Scoped withdraw policy; UI checks rows affected |
| 9 | Medium | Three notifications per application status change | Single `notify_application_events` trigger |
| 10 | High | `send-sport-email` edge function callable without auth | Constant-time service-key Bearer check |
| 11 | Low | Digest email re-sent daily and included expired opportunities; N+1 fetch | 6-day dedupe, expiry filter, single fetch |
| 12 | Low | Sitemap listed expired opportunities | Filter on `closing_date` |
| 13 | Medium | `date_of_birth` selectable by `anon` | Column privilege revoked |

## Observations not fixed (need a decision or runtime)
- Email send loop has no claim/lock; two concurrent runs can double-send.
- Storage objects are not removed when an account is deleted.
- After withdrawing, an athlete cannot re-apply (unique constraint); product decision needed.
- No test coverage for RLS; regressions would be silent.
- No `supabase/config.toml`, so local dev and CI cannot reproduce auth/storage settings.

## Suggested upgrades
1. **pgTAP RLS suite in CI** using the attack scripts used here as the seed. Highest value for the lowest cost.
2. **PayFast ITN webhook edge function**: verify signature, reconcile with `sport_service_orders`, activate entitlements server-side.
3. **Email**: Resend preferences, one-click unsubscribe headers, send queue with row claiming.
4. **Observability**: Sentry and GA4 behind a consent banner (CSP already allows planned hosts, check on enabling).
5. **SEO**: edge-injected per-opportunity meta and JobPosting-style structured data on Cloudflare; sitemap index when over 50k URLs.
6. **Storage lifecycle**: cleanup on deletion, size and MIME limits, signed URLs for private media.
7. **Dependency hygiene**: Dependabot, `npm audit` in CI, lockfile enforcement.

## Suggested new features and services (ordered by revenue and trust)
